# Лабораторная работа №3, вариант 13

K применений свёртки к матрице вещественных чисел. Linux/WSL, C11, pthreads.
Исходное ТЗ: `docs/assignment.odt`. Пользователь вводит размеры и все значения
матрицы, нечётный размер квадратного ядра, его коэффициенты и положительное K.

## Сборка и удобный ввод

```sh
cd /mnt/c/Projects/os-labs/lab3
make
./convolution --threads 4
```

Программа подсказывает каждый шаг. Матрица и ядро вводятся построчно, значения
разделяются пробелами, дробная часть — точкой (`-1.5`, `2e-3`). При неверной
строке терминальный ввод повторяется целиком; принятые строки сохраняются.
Ctrl+D завершает ввод, нехватка данных считается ошибкой. Все размеры и K
положительные. Нечётная сторона ядра задаёт однозначный центральный элемент.
Ядро может быть больше исходной матрицы. Числа NaN и Inf не принимаются.
Значения хранятся как double; представимые субнормальные числа допускаются,
а слишком маленькие ненулевые числа, округляющиеся при вводе в ноль, отклоняются.

```sh
./convolution --help
./convolution --threads 4 < examples/input.txt
```

Формат файла: строка `rows cols`, затем `rows` строк по `cols` значений,
строка размера ядра, строки ядра, строка K. Это тот же формат, что в терминале.
При неверном файле программа сразу сообщает об ошибке и возвращает ненулевой код.
Подсказки, PID, число потоков и время идут в stderr; в stdout только результат.
Пример в `examples/` использует единичное ядро и сохраняет исходную матрицу.

## Алгоритм и границы

Размер результата совпадает с исходным. За границами матрицы значения равны нулю.
Используется именно свёртка, то есть ядро переворачивается по обеим осям:

`result[i,j] = sum(kernel[u,v] * source[i + center - u, j + center - v])`.

Коэффициенты не нормализуются автоматически: для усреднения введите, например,
ядро 3x3 из коэффициентов `0.1111111111111111`. Каждый из K проходов получает
результат предыдущего. Два буфера меняются ролями только после завершения всех
потоков. Переполнение вычислений до NaN/Inf приводит к ошибке без вывода матрицы.

## Потоки и структура

`--threads P` ограничивает ВСЕ одновременно работающие потоки программы,
включая главный. Значение по умолчанию 1. Фактическое число — `min(P, rows)`.
Главный поток считает один диапазон строк; остальные считают непересекающиеся
диапазоны. `pthread_join` синхронизирует завершение каждого прохода; гонок записи
между строками нет. Потоки создаются заново на каждом проходе: это простая
реализация, накладные расходы включены в измеренное время.

- `src/matrix.c` — матрица, проверка размеров и свёртка диапазона строк.
- `src/filter.c` — разбиение строк, pthread, ожидание и K проходов со сменой буферов.
- `src/console.c` — ввод, подсказки, проверки и вывод.
- `src/main.c` — параметры запуска, измерение времени и освобождение памяти.

Все функции C и вспомогательных Python-скриптов — не более 40 строк,
`main` — не более 20 строк; `goto` не используется. Проверка входит в `sh tests/run.sh`.

## Проверки и исследование

```sh
sh tests/run.sh
python3 tests/benchmark.py
```

Измеряется только фильтрация: выделение вспомогательного буфера, вычисления,
создание и ожидание потоков. Чтение/печать матрицы не входят во время.
`tests/benchmark.py` сравнивает одинаковые данные, проверяет совпадение результатов,
выполняет прогрев и повторные чередующиеся запуски. Ускорение `S = T1 / Tp`,
эффективность `E = S / P`, где P включает главный поток.

Посмотреть потоки работающего процесса из второго терминала:

```sh
ps -L -p PID -o pid,tid,nlwp,stat,comm
```

PID программа печатает перед расчётом. Для наблюдения нужны достаточно большие
матрица, ядро и K. Автоматизированная проверка: `python3 tests/threads.py`.
