## 1. Что нужно выполнить по заданию

Нужно написать программу на C, которая обрабатывает данные многопоточно средствами ОС. Число одновременно существующих потоков ограничивается ключом запуска. Нужно показать потоки стандартным средством ОС и исследовать ускорение и эффективность на разных данных и количествах потоков.

Вариант 13: K раз применить фильтр с матрицей свёртки к матрице вещественных чисел. Размер окна задаёт пользователь.

В нашей программе пользователь вводит:

1. Число строк и столбцов исходной матрицы.
2. Её значения по строкам.
3. Нечётную сторону квадратного ядра.
4. Коэффициенты ядра по строкам.
5. Число проходов K.

Лимит потоков передаётся как `--threads P`. Язык — C11, библиотека потоков — POSIX pthreads. Главный поток входит в P и тоже считает строки.

## 2. Что здесь означает фильтр

Фильтр — правило вычисления нового значения ячейки по значениям в её окрестности. Маленькая матрица коэффициентов называется ядром. Она задаёт веса соседних элементов.

Например, ядро усреднения 3×3:

```text
1/9  1/9  1/9
1/9  1/9  1/9
1/9  1/9  1/9
```

Оно заменяет значение средним по девяти позициям. Для участка

```text
1 2 3
4 5 6
7 8 9
```

новое центральное значение: `(1 + 2 + ... + 9) / 9 = 5`.

Более показательный случай: если центр равен 9, а восемь соседей нулевые, новое центральное значение равно 1. Большой одиночный пик сглаживается.

В консоли нельзя писать `1/9` как выражение: программа читает числа, а не вычисляет выражения. Вводите `0.1111111111111111`. Автоматической нормализации коэффициентов нет. Ядро из девяти единиц вычисляет сумму, а не среднее.

## 3. Как выполняется свёртка

Для одной выходной ячейки:

1. Центр ядра совмещается с координатой ячейки.
2. Ядро переворачивается по обеим осям.
3. Коэффициенты умножаются на соответствующие значения исходной матрицы.
4. Произведения складываются.
5. Сумма записывается в отдельную выходную матрицу.

Ядро переносится ко всем ячейкам. Для симметричного ядра усреднения переворот ничего не меняет. Для несимметричного ядра направление важно: без переворота получилась бы корреляция.

В коде используется равносильная формула:

```text
B[row,col] = Σ H[u,v] × A[row + center - u, col + center - v]
center = M / 2
```

Ядро физически не копируется и не переворачивается: обратное направление задано индексами `center - u` и `center - v`.

Размер результата равен размеру входа. Значения за границами входной матрицы считаются нулями. Для усредняющего ядра это означает, что сумма у краёв тоже делится на 9, а не на число реально существующих соседей.

Например, в левом верхнем углу матрицы с числами 1–9 окно содержит только `1, 2, 4, 5`; остальные позиции нулевые. Результат: `12 / 9`, а не `12 / 4`.

Если K=3, вычисляется цепочка `A0 → A1 → A2 → A3`. Каждый проход читает результат предыдущего, а не исходную матрицу заново.

Четыре цикла в прямом алгоритме естественны: два перебирают выходные ячейки, ещё два — коэффициенты ядра. За K проходов получается `O(K × R × C × M²)` операций.

## 4. Процесс и поток

Процесс содержит адресное пространство и ресурсы работающей программы. Поток — отдельный ход выполнения внутри процесса. У него собственное состояние исполнения и стек, но память процесса доступна другим его потокам.

В этой лабе один процесс `convolution`: главный поток и созданные работники. Матрицы лежат в общей куче; передавать их через pipe не нужно. Переменные циклов и сумма внутри вызова `convolve_rows` принадлежат конкретному вызову функции.

Собственный стек не является защитой памяти: если передать указатель на локальный объект другому потоку, тот может обращаться к нему, пока объект существует. Поэтому жизненный цикл аргумента нужно контролировать.

Источник: [Linux pthreads(7)](https://man7.org/linux/man-pages/man7/pthreads.7.html).

## 5. Конкурентность и параллельность

Конкурентность означает, что несколько работ продвигаются в перекрывающиеся периоды времени. На одном ядре это возможно за счёт переключений. Параллельность означает одновременное выполнение на разных вычислительных ресурсах.

Создание четырёх потоков само по себе не гарантирует, что четыре потока постоянно исполняются одновременно. Это зависит от доступных процессоров и планировщика. Для CPU-bound свёртки полезная параллельность требует вычислительных ресурсов.

Число потоков, число физических ядер и число логических процессоров — разные величины.

## 6. Пользовательские и ядерные потоки

В теории ОС различают потоки, которыми управляет пользовательская библиотека, и потоки, известные планировщику ядра; существуют также смешанные модели. Это одна из тем авторского фрагмента о потоках.

В современной Linux-библиотеке NPTL pthread-потоки соответствуют планируемым сущностям ядра по модели 1:1. Поэтому их можно увидеть через `ps -L`. `pthread_t` — идентификатор библиотечного интерфейса; его нельзя автоматически считать числом из столбца Linux TID.

Источник реализации: [pthreads(7), Linux implementations](https://man7.org/linux/man-pages/man7/pthreads.7.html).

## 7. Создание потока и аргументы

Вызов в программе:

```c
pthread_create(&tasks[i].thread, NULL, run_rows, &tasks[i]);
```

Он сохраняет идентификатор работника в `thread`, использует стандартные атрибуты и запускает `run_rows`, передав адрес индивидуального задания. Данные не копируются автоматически: передаётся указатель.

Успех — код 0, ошибка — возвращённый код ошибки. Нельзя безусловно объяснять неудачу через `perror`, не обработав этот код.

Каждому работнику передаётся собственный `RowTask`. Массив заданий живёт до окончания всех работников. Опасным вариантом было бы передавать всем адрес одной изменяемой переменной цикла или освобождать массив сразу после создания потоков.

Источник: [pthread_create(3)](https://man7.org/linux/man-pages/man3/pthread_create.3.html).

## 8. Распределение строк и балансировка

Программа распределяет данные: каждый поток выполняет одинаковую операцию над своим диапазоном строк. Диапазон полуоткрытый: `[first_row, end_row)`.

Для R строк и P участников:

```text
chunk = R / P
remainder = R % P
```

Первые `remainder` участников получают дополнительную строку. Например, R=10 и P=3 дают диапазоны `[0,4)`, `[4,7)`, `[7,10)`: 4, 3 и 3 строки.

Плановый предел равен `min(лимит, число строк)`. Для двух строк при `--threads 8` используются максимум два участника. Для P=1 работники не создаются.

Равное число строк примерно балансирует работу, но стоимость краевых строк может отличаться: часть ядра выходит за границы и пропускается. Также ОС может предоставлять участникам разное процессорное время. Фактические причины разброса отдельно не профилировались.

Общий принцип разбиения на независимые задачи: [LLNL, Designing Threaded Programs](https://hpc-tutorials.llnl.gov/posix/designing_threaded_programs/).

## 9. Гонка данных и почему общего массива недостаточно для проблемы

Гонка возникает при несинхронизированных конфликтующих обращениях к одной области памяти, когда хотя бы одно обращение изменяет её. Простое одновременное чтение не является гонкой.

В нашем проходе все участники читают `source` и `kernel`, но записывают разные строки `destination`. Отдельное поле результата есть у каждого задания. Главный читает его только после завершения работника.

Это позволяет обойтись без мьютекса вокруг каждой ячейки. Общая память безопасна благодаря организации доступа, а не потому, что сама матрица автоматически защищена. `const Matrix *` также не является блокировкой и не обеспечивает глубокую неизменяемость буфера `data`.

Источник правил доступа и синхронизации: [POSIX, Memory Order and Consistency](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html).

## 10. Зачем нужен join

`pthread_join` ожидает завершения конкретного работника. После успешного ожидания можно использовать его результат и освобождать память задания. Если работник уже завершился, ожидать его заново по времени не нужно.

В программе порядок такой:

```text
запустить работников → посчитать главный диапазон → дождаться работников
→ проверить результаты → поменять входной и выходной буферы
```

Так следующий проход не читает незавершённые строки. Ожидания выполняются последовательно в цикле, но вычисления работников от этого не становятся последовательными: они уже были запущены.

`join` ожидает завершение потока; отдельный барьер обычно позволяет существующим потокам дождаться друг друга и продолжить работу. В нашем варианте работники заканчивают работу после одного прохода.

Источник: [POSIX pthread_join](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_join.html).

## 11. Другие средства синхронизации

| Средство | Назначение | Связь с лабой |
|---|---|---|
| Мьютекс | Исключительный доступ к защищаемым данным | Не нужен для непересекающихся выходных строк |
| Семафор | Учёт разрешений/ресурсов | Мог бы ограничивать доступ, но здесь число работников ограничено при создании |
| Условная переменная | Ожидание изменения условия совместно с мьютексом | Пригодилась бы в пуле работников, которого здесь нет |
| Барьер | Ожидание заданного числа участников на границе этапа | Альтернатива для постоянных работников между проходами |
| Join | Ожидание завершения конкретного потока | Используется в нашей реализации |

Синхронизация не сводится к мьютексам. Здесь необходимый порядок обеспечивается завершением работников и `join`.

Источник определения барьера: [POSIX pthread_barrier_wait](https://pubs.opengroup.org/onlinepubs/009696899/functions/pthread_barrier_wait.html). Мьютекс: [POSIX pthread_mutex_lock](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_mutex_lock.html).

## 12. Два буфера и зависимость между проходами

Результат одной ячейки зависит от соседей предыдущей матрицы. Если записывать прямо поверх входа, следующие ячейки могут прочитать уже изменённых соседей. Результат станет зависеть от порядка обхода; при нескольких потоках возможны и гонки.

Поэтому один буфер только читается, второй заполняется. После успешного завершения прохода меняются указатели. Размер матрицы при этом не меняется, копирование всех элементов не требуется.

На обычном пути `main` освобождает текущее содержимое матрицы и ядро, а `apply_filter` — второй матричный буфер. При ошибке после нескольких успешных проходов исходный объект уже может содержать результат последнего успешного прохода: операция не обещает откат к первоначальному вводу.

## 13. Взаимоблокировка и время жизни данных

Взаимоблокировка — ситуация, когда участники ждут друг друга и никто не может продолжить. Простейший пример: главный ждёт работника, а работник ждёт действие главного, которое произойдёт только после этого ожидания.

В нашей схеме работники вычисляют строки и не ждут главного; главный ожидает их в конце прохода. Если создание очередного потока не удалось, нужно дождаться уже запущенных, а затем освобождать задания.

Если сам `pthread_join` возвращает ошибку, код немедленно завершает процесс через `_Exit`. Он не освобождает память при неизвестном состоянии работника. Это аварийная ветка, а не обычный способ завершения программы.

## 14. Планирование и накладные расходы

Планировщик выбирает, каким готовым потокам предоставить процессор. Во время свёртки поток в основном считает; при ожидании завершения другого участника он может быть заблокирован.

В этой реализации работники создаются на каждом проходе. Для K проходов и P участников создаётся всего `K × (P - 1)` работников, хотя одновременно существует не более P потоков приложения. Например, K=2 и P=4 означают шесть созданий за весь запуск.

Поток требует ресурсов, включая стек и состояние исполнения. Увеличение числа потоков не является бесплатной операцией. В данной программе затраты создания, распределения работы и ожидания включены во время фильтрации.

## 15. Ускорение, эффективность и закон Амдала

Для одинакового входа:

```text
S(P) = T(1) / T(P)
E(P) = S(P) / P
```

Если один участник тратит 10 секунд, а четыре — 4 секунды, ускорение равно 2.5, эффективность — 0.625. В нашей методике P включает главный поток, который тоже вычисляет строки.

Если доля последовательной работы равна s, идеализированная модель Амдала даёт:

```text
S(P) = 1 / (s + (1 - s) / P)
```

Последовательная часть ограничивает масштабирование. Реальные расходы синхронизации и управления потоками дополнительно влияют на время. На маленькой матрице расходы могут превысить выигрыш от разделения вычислений.

Источник теории масштабирования: [LLNL, Introduction to Parallel Computing](https://hpc.llnl.gov/documentation/tutorials/introduction-parallel-computing-tutorial).

## 16. Что реально измерено в этой лабе

Итоговые данные лежат в `report/inc/benchmark.csv`, `summary.json` и `machine.json`. Условия: WSL2, GCC 13.3.0, матрицы 128×128, 512×512 и 1024×1024; ядро 5×5; K=20; P=1,2,4,8. После прогрева выполнены пять повторов с перемешанным порядком P. В таблице используются медианы; диапазоны времени сохранены.

Время охватывает фильтрацию, выделение вспомогательного буфера и работу с потоками. Консольный ввод и печать в него не входят. SHA256 подтверждает одинаковый вывод между разными P; математическую правильность отдельно проверяет набор тестов.

На 1024×1024 при P=8 получено ускорение около 4.25, эффективность 0.531. На 128×128 многопоточность замедлила обработку. Значение эффективности около 1.006 при P=2 на большом размере не доказывает сверхлинейное масштабирование: такое малое превышение сопоставимо с шумом измерений.

Это результаты данной машины и нагрузки. Нельзя утверждать, что восемь потоков всегда лучше. Причины колебаний — нагрузка ОС, планирование, частоты и память — здесь не измерены по отдельности.

## 17. Как показать потоки

```bash
./convolution --threads 4
```

Перед расчётом программа печатает PID. Во втором терминале:

```bash
ps -L -p PID -o pid,tid,nlwp,stat,comm
```

PID — процесс, TID — отдельный Linux-поток, NLWP — число потоков процесса. На слишком коротком запуске можно не успеть увидеть работников. Автоматический сценарий `python3 tests/threads.py` использует длительный расчёт.

`ps` даёт периодические снимки. Это наблюдённое число, а не доказательство каждого мгновения работы. Верхний предел дополнительно следует из кода; `strace` показывает системные события создания и завершения. Протоколы сохранены в `report/inc/threads.txt` и `threads-trace.txt`.

## 18. Детали C, которые нужно понимать по коду

- `size_t` хранит размеры и не бывает отрицательным. Для координаты за верхним/левым краем нужен знаковый `ptrdiff_t`; приведение выполняется до вычитания.
- Матрица хранится одним массивом: адрес элемента задаётся индексом `row * cols + col`.
- Перед выделением памяти нужно проверить переполнение произведений размеров.
- `double` хранит вещественные значения приближённо. `isfinite` отбрасывает NaN и бесконечность.
- `malloc` не заполняет память значениями матрицы: их читает пользовательский ввод. Рабочий буфер заполняется вычислением каждого элемента.
- `static` у функции ограничивает её видимость данным C-файлом.
- Возвращаемые 0 и -1 — соглашение наших функций. У `parse_options` код 1 отдельно означает показанную справку.

Это пояснения языка и нашего проекта; их не следует выдавать за полный перечень того, что изложено у Таненбаума.

## 19. Команды для работы

`make` собирает, но не запускает программу. `up to date` означает, что пересборка не требуется. Исполняемый файл запускается через `./convolution`.
